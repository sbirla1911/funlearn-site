# FUNlearn — Video Generation Pipeline (v1 technical spec)

> Companion to [video-vision.md](./video-vision.md). This is *how* we build the video described there.
> Scope: the projectile × football reference case, built so new concepts/interests slot in.

---

## Core principle: split **art** from **truth**
- **Truth** (numbers, angles, trajectory, equations, diagram geometry) → computed by deterministic
  code. Never invented by a model.
- **Art** (the kid, the pitch, the aesthetic scene) → generated by an image model.
- The two meet at **compositing**: code draws the correct overlay *on top of* the generated art.

This is what makes "accuracy is the top KPI" structurally true instead of a hope.

---

## Pipeline (one video request → one playable lesson)

```
(concept, interest, grade)
   │
   1. Cache check  ──hit──▶ serve cached video
   │ miss
   2. Concept card  ── vetted truth: formulas + variables + ordered teach-moments
   │
   3. Physics engine ── compute exact trajectory, vectors, range, apex, values  (TRUTH)
   │
   4. Storyboard LLM ── scenes + narration + captions + image-prompts
   │                    (references engine values by key — invents no numbers)
   │
   5. Image gen ──────── one still per scene  (ART: fixed character desc + seed + palette)
   │
   6. Overlay layer ──── code draws arrows/curve/angle/equation/values via SVG  (TRUTH on ART)
   │
   7. TTS ───────────── narration audio + word timings (for caption sync)
   │
   8. Assembly ───────── timed web player: motion segments + teach-pause segments
   │
   9. Accuracy check ── validate overlays vs. concept card (auto) + optional human spot-check
   │
   10. Cache & serve
```

Stages 3 and 6 are the only places truth lives; 4 and 5 can be as "creative" as we like without
risking the science.

## Data contracts (the important part)

### Concept card (hand-vetted, one per concept — the source of truth)
```jsonc
{
  "id": "projectile-motion",
  "subject": "physics",
  "variables": { "v": "launch speed (m/s)", "theta": "launch angle (deg)", "g": 9.81 },
  "model": "projectile",            // selects the physics engine function
  "teachMoments": [                 // ordered; engine + storyboard both honor this
    { "key": "launch",  "idea": "force gives the ball speed in a direction", "values": ["v","theta"] },
    { "key": "ascent",  "idea": "gravity constantly pulls down; vertical speed shrinks", "values": ["vy","g"] },
    { "key": "apex",    "idea": "at the top, vertical speed is zero", "values": ["tApex","hMax"] },
    { "key": "descent", "idea": "symmetric fall back to the ground", "values": ["vy"] },
    { "key": "recap",   "idea": "range, height and angle all come from v and theta",
      "values": ["range","hMax","theta","tFlight"] }
  ],
  "equations": {                    // rendered verbatim for higher grades
    "range": "R = v^2 * sin(2*theta) / g",
    "hMax":  "H = v^2 * sin^2(theta) / (2*g)",
    "tFlight": "T = 2*v*sin(theta)/g"
  }
}
```

### Physics engine output (deterministic — the truth for THIS video)
```jsonc
{
  "inputs": { "v": 20, "theta": 55, "g": 9.81 },
  "derived": { "range": 38.3, "hMax": 13.7, "tFlight": 3.34, "tApex": 1.67, "vy0": 16.4, "vx": 11.5 },
  "arc": [ [0,0], [2.3,3.1], /* …sampled x,y points for the curve… */ [38.3,0] ],
  "vectors": { "launch": {"at":[0,0],"dir":55,"mag":20},
               "apex":   {"at":[19.1,13.7],"gravity":{"dir":-90}} }
}
```

### Storyboard (LLM output — words & framing, values only by reference)
```jsonc
{
  "grade": 9,
  "scenes": [
    { "type": "motion", "beat": "open",
      "imagePrompt": "<character> kicking a football, slow-motion, side view, <palette/style>",
      "durationHint": "short" },
    { "type": "teach-pause", "teachMoment": "launch",
      "imagePrompt": "close-up of boot striking the ball, side view, <palette/style>",
      "overlay": "forceVector",                 // tells stage 6 what to draw
      "caption": "The kick gives the ball a push — a force.",
      "narration": "When the boot hits the ball, it gives it a force: a push with a size and a direction.",
      "showValues": ["v","theta"] },             // pulled from engine output, not written by LLM
    // …ascent / apex / descent …
    { "type": "teach-pause", "teachMoment": "recap",
      "overlay": "fullTrajectory",
      "caption": "Angle + power decide how far and how high.",
      "narration": "...",
      "showEquations": ["range","hMax"] },        // included for grade ≥ ~9, hidden for younger
    { "type": "check", "prompt": "If she kicked it flatter, would it travel farther or land sooner?",
      "answer": "..." }
  ]
}
```

**Grade dial** acts here: the LLM writes narration at the right reading level, and `showEquations`/
extra teach-pauses are included or dropped by grade — same engine output underneath.

## Rendering / assembly (v1)
- **Web player, client-side**, driven by the storyboard JSON + generated image assets + audio —
  a natural evolution of the current `LessonLauncher` / `AnimatedLesson` modal.
- **Motion segments:** gentle Ken-Burns / parallax on the stills + CSS transitions (reuse the existing
  keyframe system in `globals.css`). Not true frame-by-frame animation — "animated feel" via motion on
  stills, exactly matching the slideshow vision.
- **Teach-pause segments:** still + SVG overlay animates in (arrows draw, angle sweeps, curve traces —
  reuse `lp-draw` / `offset-path` tricks) while the caption and voiceover play.
- **Overlay = SVG generated from engine output**, so every arrow/value is provably correct.
- Later option: server-render to MP4 (Remotion) if we need shareable downloads — not needed for v1.

## Suggested tech (confirm)
| Stage | v1 pick | Why / alternatives |
|---|---|---|
| Storyboard LLM | **Gemini** (stack already uses it, free tier) | Claude for stronger structured output if needed |
| Image gen | **Gemini image (Nano Banana / Imagen)** | character-consistency via fixed description + seed; palette baked into style prompt |
| Physics engine | **plain TypeScript** per concept | deterministic, testable, zero external cost |
| Overlay/diagram | **SVG in code** (reuse site system) | the accuracy guarantee |
| TTS | **Google Cloud TTS** (Gemini stack) | ElevenLabs if we want warmer kid voices |
| Player | **web, client-side storyboard player** | evolve `LessonLauncher` |

> **Architecture note:** generation needs server-side API calls + caching/storage, so the product
> outgrows the current static GitHub-Pages export. v1 product = Next.js with API routes (or a small
> backend) + a cache store keyed by `concept+interest+grade band`. The showcase site stays as-is.

---

## Accuracy check (stage 9) — OPEN, recommendation
For v1: **automated validation** (overlay values must equal engine output; arc endpoints must match
range; angle within tolerance) **+ a human spot-check** of each new `concept+interest+grade` the first
time it's generated, before it enters the cache. Once a concept card is trusted, regeneration for new
interests is lower-risk because the truth layer is unchanged.

---

## Build order (proposed)
1. **Physics engine + concept card for projectile** (pure functions + tests). Truth first.
2. **Overlay renderer** — feed engine output, draw the annotated trajectory as animated SVG. Verifiable
   on its own, no AI yet.
3. **Storyboard schema + a hand-written projectile storyboard** (grade 9) to drive the player.
4. **Client player** that plays motion + teach-pause segments from a storyboard (stub images first).
5. **Plug in image gen** (character desc + seed + palette) for the stills.
6. **Plug in TTS** + caption sync.
7. **Grade dial** (regenerate narration + toggle equations for a younger cut).
8. **Cache + request flow**, then a second interest (e.g. skateboarding) to prove reuse vs. fresh.

Steps 1–4 need no API keys and prove the hardest/most-important part (accuracy) first.
